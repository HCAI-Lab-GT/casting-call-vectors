Overview

pvx extracts persona vectors from transformer hidden states using contrastive activation differences. Each persona is an occupation sourced from O*NET data, tagged with RIASEC (Holland code) personality dimensions. The pipeline has three stages: generate persona definitions, extract activation vectors from a target model, and analyze the resulting geometry.

Workflows

Persona Generation (scripts/generate_vocational_personas.py) — Loads O*NET occupation data, generates 5 system prompt variants per occupation via gpt-4o-mini, saves JSON files to persona_data/vocational_personas/instructions/.
Vector Extraction (scripts/run_extraction.py) — Loads persona JSONs, runs each through a transformer model alongside a neutral baseline, captures hidden state activations, computes contrastive mean differences, saves .pt + .json per persona.
Vector Analysis (scripts/run_analysis.py) — Loads extracted vectors, runs PCA and clustering via PersonaGeometry, generates 2D/3D visualizations, optionally computes RIASEC-specific correlations and alignment scores.

Persona Generation

Execution starts at scripts/generate_vocational_personas.py. The CLI accepts --output-dir, --riasec filter, --limit, and --model (defaults to gpt-4o-mini). After argument parsing, these resolve into a loader and generator pair.

ONETLoader (src/pvx/data/onet_loader.py) reads the bundled O*NET text files and builds occupation profiles. Each profile contains a SOC code, title, description, RIASEC scores across 6 dimensions (R, I, A, S, E, C), work styles, and derived Big Five mappings. The loader determines each occupation's primary RIASEC type and highpoint codes from the raw interest scores.

These profiles feed into VocationalPersonaGenerator (src/pvx/pvx_models/vocational_dataset.py). For each occupation, the generator calls gpt-4o-mini to produce 5 distinct system prompt variants that instruct a model to behave as that professional. It also creates an evaluation prompt template for later LLM-as-judge scoring. A fallback mode (--fallback-only) skips the API and uses template-based prompts instead.

Output lands in persona_data/vocational_personas/instructions/{slug}.json. Each file contains an instruction array (5 prompt variants), an eval_prompt string, and a _metadata block with SOC code, title, RIASEC scores, primary type, and highpoint codes. Currently 153 occupations are generated.

Vector Extraction

Execution starts at scripts/run_extraction.py. The CLI accepts --persona or --persona-dir, --model (default: allenai/OLMo-7B-Instruct), --layer (default: 14), --num-questions (default: 50), and optional --track for run lifecycle management via RunConfig.

load_personas_from_path() iterates over JSON files and yields VocationalPersonaSource instances (src/pvx/sources/vocational.py). Each source implements the PersonaSource protocol: get_system_prompts() returns the 5 prompt variants, get_baseline_prompts() returns neutral prompts from a shared BaselineSource (empty string, "You are an AI assistant.", etc.), and get_metadata() returns the RIASEC-tagged PersonaMetadata.

QuestionBank (src/pvx/extraction/questions.py) loads 240 standardized extraction questions from _vendor/assistant-axis/data/extraction_questions.jsonl, with a 20-question fallback set if that file is absent. The pipeline samples N questions per persona with reproducible seeds.

Pipeline overview: O*NET data through generation, extraction, and analysis

ExtractionPipeline (src/pvx/extraction/pipeline.py) orchestrates the core loop. extract_batch() iterates over persona sources. For each persona, extract_persona() samples N questions, then for each question:

  1. Calls ActivationExtractor.extract() with the persona system prompt and the question. The extractor tokenizes the input into chat format, runs a forward pass to capture the prompt's last-token hidden state at the target layer, then generates a response token-by-token using top-p sampling with KV-cache, accumulating hidden states at each step.
  2. Calls extract() again with the baseline prompt and the same question, producing a second ActivationResult.
  3. Optionally passes both responses through an LLMJudge for quality filtering (skip if persona scores below threshold).
  4. Accumulates persona and baseline activation tensors across valid pairs.

After all questions, the pipeline computes contrastive differences: mean(persona_activations) - mean(baseline_activations) for three extraction points: last prompt token, response mean, and all-layers response mean. The result is a PersonaVector dataclass saved as two files: a .pt file containing the three difference tensors, and a .json file with persona metadata and extraction statistics.

Extraction swim-lane: call chain from CLI through pipeline to storage

Checkpointing happens after each persona (checkpoint_every=1). If interrupted, --resume reloads completed vectors from the output directory and skips them. When --track is enabled, RunConfig captures the git hash, model slug, timestamps, and structures outputs into outputs/runs/{model_slug}/{run_id}/vectors/.

Vector Analysis

Execution starts at scripts/run_analysis.py. The CLI accepts --vectors-dir (required), --n-pcs (default: 10), --output-dir, and optional --wandb-project for experiment tracking.

load_vectors() reads all .pt files in the vectors directory. It extracts the response_mean_diff tensor from each file and pairs it with metadata from the corresponding .json. These form the inputs to PersonaGeometry.

PersonaGeometry (src/pvx/analysis/geometry.py) stacks the vectors into a matrix and provides: compute_pca() for dimensionality reduction, cluster() for k-means or hierarchical clustering (default 6 clusters), compute_distances() for pairwise cosine/Euclidean distances, and correlate_with_metadata() for linking PC projections to numeric metadata fields.

For RIASEC-specific analysis (src/pvx/analysis/riasec.py), analyze_riasec() computes PC-RIASEC correlations, builds contrast vectors for the three opposite pairs (Realistic-Social, Investigative-Enterprising, Artistic-Conventional), calculates an alignment score (mean of max absolute cosines), and evaluates against a 0.6 threshold for a go/no-go signal.

PersonaVisualizer (src/pvx/analysis/viz.py) generates matplotlib plots (PCA 2D/3D, variance explained, distance matrix, cluster assignments) and interactive Plotly HTML. When W&B is enabled, all plots and metrics are logged to the dashboard. Results save to outputs/analysis/ as PNG, JSON, and HTML.
