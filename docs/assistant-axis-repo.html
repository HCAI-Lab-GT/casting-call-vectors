Overview

This repository accompanies the paper "The Assistant Axis: Situating and Stabilizing the Default Persona of Language Models" (Lu et al., 2026). It provides a complete toolkit for computing, analyzing, and intervening on a direction in activation space—the Assistant Axis—that captures how "Assistant-like" a language model's current persona is.

The codebase has two main parts: a 5-step pipeline in pipeline/ that computes the axis from scratch for any model, and a Python library in assistant_axis/ that loads pre-computed axes and applies steering or monitoring at inference time. Jupyter notebooks in notebooks/ provide interactive analysis (PCA, visualization, steering demos). Conversation transcripts from the paper live in transcripts/.

Core Concept

Large language models default to a "helpful Assistant" persona cultivated during post-training. This persona can drift during conversations—particularly in emotionally charged or meta-reflective contexts—leading to harmful behavior. The Assistant Axis captures this phenomenon as a measurable direction in the model's hidden states.

axis = mean(default_activations) − mean(role_activations)

The axis points toward default Assistant behavior. Higher projections onto the axis indicate more "Assistant-like" responses (transparent, grounded, helpful); lower projections indicate drift toward role-playing personas (enigmatic, subversive, dramatic). Workflows

Axis Computation Pipeline (pipeline/1_generate.py → 5_axis.py) — Generates model responses for 275 character roles, extracts hidden-state activations, scores role adherence with an LLM judge, computes per-role mean vectors, and aggregates them into the final Assistant Axis. This is the one-time offline computation.
Inference-Time Steering (assistant_axis.steering) — Loads a pre-computed axis and applies activation interventions (addition, ablation, capping) during model generation via PyTorch forward hooks. Used to push model behavior toward or away from the Assistant persona.
Inference-Time Monitoring (assistant_axis.axis + assistant_axis.internals) — Extracts activations from conversations, projects them onto the axis, and returns a scalar measuring how "Assistant-like" the model is at each turn. Used to detect persona drift in real time.
Interactive Analysis (notebooks/) — Jupyter notebooks for PCA analysis of role vectors, axis visualization with cosine similarity, steering demos, and transcript projection to visualize persona trajectories over conversations.

Pipeline: Input → Processing → Output

The pipeline computes the Assistant Axis from scratch. It is orchestrated by pipeline/run_pipeline.sh or by running each of the 5 numbered scripts individually. All scripts support checkpointing—they skip already-completed work on restart.

Data flow: role definitions and questions through the 5-step pipeline to the final axis tensor

1 Generate Responses

Execution starts at pipeline/1_generate.py. The CLI takes --model (a HuggingFace model name) and --output_dir. The script instantiates a RoleResponseGenerator from assistant_axis/generation.py, which wraps a VLLMGenerator for high-throughput batch inference. It loads 275 role JSON files from data/roles/instructions/—each containing 5 system prompt variants—plus a default.json with neutral prompts like "You are an AI assistant." It also loads 240 extraction questions from data/extraction_questions.jsonl.

For each role, the generator produces 1,200 responses (5 prompts × 240 questions) via vLLM batch inference, formatting each as a [system, user] conversation and appending the generated assistant reply. Results are saved as {role}.jsonl files, each line containing the conversation, system prompt, prompt index, question index, and question text. Multi-GPU tensor parallelism is supported.

2 Extract Activations

pipeline/2_activations.py takes the response JSONL files and extracts mean hidden-state activations. It loads the model via ProbingModel from assistant_axis/internals/model.py, which wraps a HuggingFace model and provides access to post-MLP residual stream outputs at each layer.

For each role's responses, conversations are batched and fed through the model. ActivationExtractor captures hidden states at specified layers, and SpanMapper maps token-level activations to per-turn means by identifying assistant turn boundaries. The result for each conversation is a tensor of shape (n_layers, hidden_dim)—the mean activation across all assistant tokens. These are saved as {role}.pt files keyed by {label}_p{prompt}_q{question}.

3 Score with LLM Judge

pipeline/3_judge.py can run in parallel with step 2 (both only need step 1's output). It scores how well each response adheres to its assigned role using an LLM judge (GPT-4.1-mini by default via the OpenAI API). Each role JSON file contains an eval_prompt template with {question} and {answer} placeholders.

The judge uses the RateLimiter and call_judge_batch from assistant_axis/judge.py for async concurrent API calls. Scores are integers 0–3: 0 = refused to answer, 1 = identified as AI but attempted answer, 2 = identified as AI with some role attributes, 3 = fully playing the role. Scores are saved as {role}.json files mapping response keys to score values.

4 Compute Per-Role Vectors

pipeline/4_vectors.py merges activations with scores. For each regular role, it filters activations to only those with score=3 (fully role-playing), requires a minimum of 50 qualifying samples (configurable via --min_count), and computes their mean. For the default role, it takes the mean of all activations (no score filtering needed). Each result is a tensor of shape (n_layers, hidden_dim) saved as {role}.pt.

5 Compute the Axis

pipeline/5_axis.py loads all per-role vectors and separates them into default vectors and role vectors. It stacks each group, computes the mean across roles, and subtracts: axis = mean(default) - mean(roles). The output is a tensor of shape (n_layers, hidden_dim) saved as axis.pt. The script reports per-layer norms to help identify which layers carry the strongest signal.

Usage: Steering & Monitoring

Once the axis is computed (or loaded from HuggingFace), the assistant_axis library provides three inference-time capabilities:

Swim-lane: steering via forward hooks and monitoring via axis projection

Activation Steering

ActivationSteering in assistant_axis/steering.py is a context manager that registers PyTorch forward hooks on specified transformer layers. During model.generate(), the hook fires after each layer's forward pass and modifies the hidden states in-place. Four intervention types are supported:

  • Addition: x + coeff * axis — standard activation steering. Positive coefficient = more Assistant-like.
  • Ablation: Projects out the axis direction, then adds back with a coefficient. At coefficient=0, the axis component is fully removed.
  • Mean Ablation: Replaces the axis component with a mean activation vector.
  • Capping: Prevents the projection onto the axis from exceeding a threshold τ. Subtracts only the excess: x - max(0, proj - τ) * axis_hat. This is the most targeted intervention from the paper, used to prevent persona drift without over-correcting normal behavior.

Activation Monitoring

The project() function in assistant_axis/axis.py takes a hidden-state tensor and the axis, normalizes the axis direction, and computes the dot product at a given layer. The result is a scalar: higher values mean the model is behaving more like the default Assistant, lower values indicate persona drift. This can be computed per-turn in a conversation to track drift over time.

For extracting activations from conversations, the internals package provides ProbingModel (model wrapper), ConversationEncoder (tokenization with turn boundary tracking), ActivationExtractor (batched hidden state capture), and SpanMapper (maps token activations to per-turn means).

Activation Capping (Paper's Primary Mitigation)

Pre-computed capping configs for Qwen 3 32B and Llama 3.3 70B are available on HuggingFace. The build_capping_steerer() function in steering.py loads an experiment config (specifying which layers to cap and at what thresholds), constructs the corresponding ActivationSteering context manager, and applies multi-layer capping during generation. This prevents the model from drifting past a safe threshold on the axis without affecting normal behavior.

Open Questions

Unknown: The internals package (ProbingModel, ActivationExtractor, SpanMapper) has no public documentation beyond its use in the pipeline.
Check: assistant_axis/internals/model.py and assistant_axis/internals/activations.py for the full API surface.
